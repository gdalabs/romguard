Hash verification

This site hosts no ROM files. It records which URL served which file, with which hash, on which date. This reduces redistribution risk while providing a useful verification record.

Current record count

0 records

No records yet. Only hashes computed locally from downloaded files are accepted, records are added as verification completes. Hashes are not copied from upstream listings, which could themselves be compromised.

How to verify

Check whether a downloaded file matches the one recorded at verification time.

macOS / Linux

shasum -a 256 miui_XXXX.tgz
# Or
sha256sum miui_XXXX.tgz

Windows (PowerShell)

Get-FileHash .\miui_XXXX.tgz -Algorithm SHA256

Windows (Command Prompt)

certutil -hashfile miui_XXXX.tgz SHA256

What hashes can and cannot detect

Can detectDownload corruption, replacement by intermediate mirrors, and files from impersonation sites. This reduces the risk of flashing a corrupted ROM.
Cannot detectA compromised upstream. A malicious file already present when the hash was recorded will still match. For independently modified builds such as xiaomi.eu, a third party cannot establish an upstream signature chain to the downloaded file.

Hash verification checks the delivery path from a source you have chosen to trust. Trust in the distributor is a separate decision that this site cannot guarantee.

Record format

/data/roms.json is the dataset itself. Each record has this shape.

{
  "id": "…",
  "device": "…",
  "rom": "xiaomi.eu 2.0.x",
  "source_url": "https://example.invalid/upstream-download",
  "sha256": "64-hex-characters",
  "size": 0,
  "verified_at": "2026-08-09"
}

scripts/validate.mjs rejects mirror_url and hashes copied from upstream listings. The policy is enforced in code because prose alone can be overlooked.
